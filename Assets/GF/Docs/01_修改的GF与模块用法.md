## 2. 你新增的模式：`ResourceMode.Resource`

文件：`qlmt/Assets/GF/GameFramework/Resource/ResourceMode.cs`

你新增了枚举值：

```csharp
Resource = 4
```

作用：

1. 给资源系统增加“Resources 直载模式”开关。  
2. 让 Runtime 和内核在同一模式标识下分支处理。  

使用方式：

1. 在 `ResourceComponent` 上把 `m_ResourceMode` 配到 `Resource`。  
2. 启动后资源系统走你加的 Resources 分支，而非版本表/更新流程分支。  

## 3. `ResourceManager` 的差异行为

文件：`qlmt/Assets/GF/GameFramework/Resource/ResourceManager.cs`

### 3.1 `SetResourceMode` 新分支

你在 `SetResourceMode(...)` 里加入了 `ResourceMode.Resource` 分支，并明确注释：

- Resources 模式不依赖版本列表、校验与更新流程。

结果：

1. 不创建 `VersionListProcessor/ResourceChecker/ResourceUpdater`。  
2. 资源初始化流程变轻，适合本地开发或轻量项目。  

### 3.2 `InitResources` 行为变化

你让 `ResourceMode.Resource` 下 `InitResources(...)` 直接完成回调并返回，不走包体版本初始化。  

结果：

1. 省去资源清单初始化链。  
2. 业务启动不再依赖版本表可用性。  

### 3.3 Update/Apply/Check 相关流程隔离

由于上述模块未创建，Resources 模式天然不走更新链路。  

注意：

1. 在此模式下调用“可更新模式专用 API”会触发不支持或条件不满足。  
2. 这是设计上的“能力裁剪”，不是 bug。

## 6. 你新增的 `ResourcesLoadResourceAgentHelper`

文件：`qlmt/Assets/GF/Scripts/Runtime/Resource/ResourcesLoadResourceAgentHelper.cs`

这个类是你这套改造的核心执行器，行为如下：

1. `ReadFile(...)`：返回占位资源对象，保持与原管线事件契约兼容。  
2. `LoadAsset(...)`：
   - 普通资源：走 `Resources.LoadAsync(...)`
   - 场景资源：走 `SceneManager.LoadSceneAsync(..., Additive)`
3. `ReadBytes/ParseBytes`：明确报错“不支持二进制资源”。  
4. `Update()`：推进异步进度并触发成功/失败事件。  
5. `Reset()`：清理当前请求状态。

使用边界：

1. 只适用于 `ResourceMode.Resource`。  
2. 资源路径必须符合 `Resources` 约定（相对路径，不带扩展名）。  
3. 不支持走文件系统二进制读取和版本包流程。

## 11. Addressables 自动透明接入（GF 内核 LoadAsset 路由 hook）

> 本节描述 **GF 内核 LoadAsset 入口注入的 Addressables 路由**，让 UI/Entity/DataTable/Sound 这些 GF 内置组件加载资源时，**自动获得 Addressables 能力**，业务层零改动。
> 这是项目对 GF 内核的第二波改造，**与 §2-10 描述的第一波（`ResourceMode.Resource`）共存**。

### 11.1 设计原则：自动透明 + 路径完全一致

| 资源所在位置 | 加载链路 | 业务侧感知 |
| --- | --- | --- |
| Addressables 群组（`Assets/AddressableAssetsData/AssetGroups/`） | **Addressables 路由优先命中** → `Addressables.LoadAssetAsync<UnityEngine.Object>` | 零感知 |
| `Resources/` 文件夹 | 路由 miss → GF 主链路 → `ResourceMode.Resource` → `ResourcesLoadResourceAgentHelper` → `Resources.LoadAsync` | 零感知 |
| 同名资源同时存在 | 优先 Addressables（路由先命中） | 零感知 |

业务侧调用 `GameEntry.UI.OpenUIForm` / `GameEntry.Entity.ShowEntity` / `GameEntry.DataTable.LoadDataTable` / `GameEntry.Sound.PlaySound` / `GameEntry.Resource.LoadAsset` 时，**完全不需要关心**资源在哪个后端。

### 11.2 GF 内核改造点

这一波改了 GF 内核，必须明确记录差异：

| 文件 | 改动 |
| --- | --- |
| `Assets/GF/GameFramework/Resource/AddressablesAssetRouter.cs`（**新增**） | 声明 `AddressablesAssetRouter`（加载）+ `AddressablesAssetReleaseRouter`（释放）两个委托类型 |
| `Assets/GF/GameFramework/Resource/IResourceManager.cs` | 新增 `SetAddressablesAssetRouter` + `SetAddressablesAssetReleaseRouter` 接口方法 |
| `Assets/GF/GameFramework/Resource/ResourceManager.cs` | 新增 2 个字段 + 2 个 setter + 2 个 `internal` 访问器 |
| `Assets/GF/GameFramework/Resource/ResourceManager.ResourceLoader.cs:320` | `LoadAsset` 入口最前端插入加载路由判定：路由命中 → return；不命中 → 走原有主链路 |
| `Assets/GF/GameFramework/Resource/ResourceManager.cs:1689` | `UnloadAsset` 入口最前端插入释放路由判定：路由命中 → return（已 Addressables.Release）；不命中 → 走 `m_AssetPool.Unspawn` |
| `Assets/GF/Scripts/Runtime/Resource/EditorResourceComponent.cs` | 实现两个接口方法（抛 `NotSupportedException`，与同文件其他 SetXxx 风格一致） |

**GF 内核保持纯净**：路由委托类型只依赖 .NET 标准库（`System.Type` + GF 自身 `LoadAssetCallbacks`），**不引用 `UnityEngine.AddressableAssets`**，所以 `GameFramework.asmdef` 不需要新增 references。

### 11.3 项目层接入实现

| 文件 | 职责 |
| --- | --- |
| `Assets/_Game/Script/Models/Asset/AddressablesAssetRouterImpl.cs`（**新增**） | 实现 `AddressablesAssetRouter` 委托：同步 `IResourceLocator.Locate` 判定 + 异步 `Addressables.LoadAssetAsync<UnityEngine.Object>` + 完成时登记反查表 + 按 `LoadAssetCallbacks` 协议派发完成事件。提供 `BeginInitialize(onComplete)` 启动入口。 |
| `Assets/_Game/Script/Models/Asset/HybridResourceHelper.cs`（**新增**） | 继承 `DefaultResourceHelper`，重写 `Release(object)`：先反查 Addressables 句柄；命中则 `Addressables.Release(handle)`，未命中走 base.Release。 |
| `Assets/_Game/Script/Models/Asset/ResourceComponentExtensions.cs`（**扩展**） | 新增 `internal static RegisterAddressablesHandle / TryReleaseAddressablesHandle / RegisterAddressablesAssetList / TryReleaseAddressablesAssetList` 4 个静态 API，供 `AddressablesAssetRouterImpl` 与 `HybridResourceHelper` 跨类调用反查表。 |
| `Assets/GF/MyGameFramework.prefab` | `m_ResourceHelperTypeName: DefaultResourceHelper → HybridResourceHelper`（位于 Assembly-CSharp 全局命名空间） |

### 11.4 启动期时序

```
GameEntry.Start
  ├─ InitBuiltinComponents  （拿 ResourceComponent 等引用，同步）
  └─ AddressablesAssetRouterImpl.BeginInitialize
       ├─ GameFrameworkEntry.GetModule<IResourceManager>().SetAddressablesAssetRouter(TryRoute)   ← 注入路由
       ├─ Addressables.InitializeAsync()                                                          ← 异步等 catalog
       └─ Completed:
            ├─ s_IsAddressablesReady = true
            └─ GameEntry.OnAddressablesReady
                 ├─ InitCustomComponents（创建 GameAssets / AddressableAssets 等）
                 └─ Invoke(InitSoundSystem)
```

**关键约束**：`InitCustomComponents` 必须在 `Addressables.InitializeAsync` 完成之后执行，否则 `GameAssetModule.BeginPreloadRequiredAssets` 触发的首批 `LoadAsset` 路由会 miss（catalog 未就绪 → `ResourceLocators` 为空 → `Locate` 返回 false）。

### 11.5 路由委托判定逻辑

```csharp
private static bool TryRoute(string assetName, Type assetType, LoadAssetCallbacks callbacks, object userData)
{
    if (!s_IsAddressablesReady) return false;                    // catalog 未就绪 → 走 GF 主链路
    if (string.IsNullOrEmpty(assetName)) return false;
    if (!TryLocate(assetName, assetType, out _)) return false;   // 同步遍历 ResourceLocators，未命中 → 走 GF 主链路

    // 命中 Addressables 群组：发起异步加载
    var handle = Addressables.LoadAssetAsync<UnityEngine.Object>(assetName);
    handle.Completed += op => {
        if (op.Status == AsyncOperationStatus.Succeeded && op.Result != null)
        {
            ResourceComponentExtensions.RegisterAddressablesHandle(op.Result, op);
            callbacks.LoadAssetSuccessCallback?.Invoke(assetName, op.Result, elapsed, userData);
        }
        else
        {
            if (op.IsValid()) Addressables.Release(op);
            callbacks.LoadAssetFailureCallback?.Invoke(assetName, LoadResourceStatus.NotExist, errorMsg, userData);
        }
    };
    return true;  // 接管成功
}
```

### 11.6 句柄释放闭环（路由优先 + 对象池兜底）

业务调 `ResourceComponent.UnloadAsset(asset)` 后，**GF 内核入口会优先咨询释放路由**：

```
ResourceManager.UnloadAsset(asset)
  ├─ 释放路由咨询 m_AddressablesAssetReleaseRouter(asset)
  │    ├─ true（Addressables 资源）：
  │    │    ├─ ResourceComponentExtensions.TryReleaseAddressablesHandle
  │    │    └─ Addressables.Release(handle) → 跳过 m_AssetPool.Unspawn ⏎
  │    └─ false（Resources 资源）：
  └─ m_ResourceLoader.UnloadAsset(asset)
        → m_AssetPool.Unspawn(asset)
        → 引用归零后 m_ResourceHelper.Release(asset) (HybridResourceHelper)
              ├─ 仅作为冗余防御：再查一次 Addressables 反查表
              └─ 未命中时：base.DefaultResourceHelper.Release（不释放 Resources 资源）
```

**为什么需要释放路由**：Addressables 路由加载的资源**并未进入 GF 的 m_AssetPool 对象池**（路由直接派发 LoadAssetSuccessCallback）。如果不拦截在 UnloadAsset 入口，`m_AssetPool.Unspawn(asset)` 会找不到该 asset 而抛 `GameFrameworkException("Can not find target in object pool")` —— 这会导致任何 UI/Entity/DataTable 关闭的场景崩溃。

### 11.7 业务调用对照表

| 业务调用 | 实际后端 |
| --- | --- |
| `GameEntry.UI.OpenUIForm("Prefabs/UI/Foo")` | Addressables 命中 → Addressables；否则 → Resources |
| `GameEntry.Entity.ShowEntity<...>(EntityDefine.Pet)` | 同上 |
| `GameEntry.DataTable.LoadDataTable<Foo>(...)` | 同上 |
| `GameEntry.Sound.PlaySound("Audio/BGM/Main")` | 同上 |
| `GameEntry.Resource.LoadAsset(path, type, callbacks)` | 同上 |

| `GameEntry.AddressableAssets.LoadAsset(...)`（薄壳收敛到扩展方法） | **强制 Addressables** |

### 11.8 使用边界

1. Addressables 路由对**所有**经由 `m_ResourceManager.LoadAsset` 的请求生效，包括 GF 内置组件与业务自调。
2. 同名资源若同时存在 `Resources/` 和 Addressables 群组，**Addressables 优先命中**；如需强制走 Resources，把资源从 Addressables 群组移除即可（不需要改业务代码）。
3. Spine `SkeletonDataAsset` / Sprite Atlas 必须把全部子资源加入同一 Addressables 群组，否则依赖加载会断。
4. Addressables.InitializeAsync 失败时（catalog 损坏 / 网络异常）`s_IsAddressablesReady` 保持 false，所有请求自动退回 GF 主链路兜底，**不会卡死游戏流程**。
5. 业务侧仍可显式调 `GameEntry.Resource.LoadAddressableAssetAsync<T>` / `GameEntry.AddressableAssets.LoadAsset` 强制走 Addressables，跳过路由判定（直调扩展方法）。

### 11.9 风险与维护提示

1. **GF 内核被改动**：`ResourceManager.cs` / `ResourceManager.ResourceLoader.cs` / `IResourceManager.cs` 升级官方 GF 时需要手动 merge 这套路由 hook；属于 §1 列出的内核差异范围内。
2. **冷启动延迟**：`Addressables.InitializeAsync` 在包体模式下约 50-200ms；`GameEntry.InitCustomComponents` 比改造前晚一帧执行，业务脚本不应在该窗口内访问 `GameEntry.GameAssets` / `GameEntry.AddressableAssets` 等自定义模块（应在 Procedure / UIForm.OnInit 等更晚阶段访问）。
3. **句柄反查表共享**：`ResourceComponentExtensions.s_HandlesByAsset` 同时被路由（GF 触发的加载）与扩展方法（业务直调）写入，键是 `UnityEngine.Object`，引用相等比较，二者互不冲突。

## 12. GF 内核改造的后续扩展方向

如果后续要继续扩展 GF 内核（即 `Resources` 后端模式本身），只建议围绕以下三点：

1. 补充 `ResourceMode.Resource` 下的能力边界文档（哪些 API 可用/不可用）。  
2. 给 `ResourcesLoadResourceAgentHelper` 增加更细的错误分类和统计。  
3. 在 Inspector 中明确标注“当前模式为 Resources，更新链路不可用”。
